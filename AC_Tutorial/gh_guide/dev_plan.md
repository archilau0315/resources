## 1. 项目定位

### 1.1 一句话定义

一部面向 Rhino 9 / Grasshopper 2 的**中英双语组件速查手册**：以原厂组件电池图标为视觉索引，按官方工具栏分类组织全部组件条目，配官方说明、端口定义、可运行示例，支持关键词检索与快速跳转。

### 1.2 与「教程」的区别

| 维度 | 教程（Tutorial） | 本手册（Reference / 速查） |
|---|---|---|
| 组织方式 | 按学习进度线性展开 | 按组件分类，随时跳查 |
| 每个条目 | 长篇分步讲解 | 一屏内看完：图标 + 端口 + 说明 + 示例 |
| 使用场景 | 从零学起 | 用的时候查、忘了就查 |
| 主要内容 | 方法与思维 | 事实与定义 |

**结论**：手册不做「从零教学」，只做「查得到、看得懂、用得上」。入门内容压缩为 1 篇快速上手，其余全部是速查。

### 1.3 目标读者

| 读者 | 需求 | 对应部分 |
|---|---|---|
| GH1 老用户 | 迁移到 GH2，想知道组件换了什么、新增了什么 | 快速上手 + GH1→GH2 对照 |
| GH2 新用户 | 不认识组件图标，需要看图找组件 | 组件速查（图标索引） |
| 参数化从业者 | 查端口类型、数据树行为、示例文件 | 组件详情 + 示例库 |
| 脚本/插件开发者 | 查 API、写自定义组件 | 脚本与插件速查 |

### 1.4 技术栈

| 项 | 版本 / 说明 |
|---|---|
| Rhino | 9.0.26300.09401（本机安装于 `C:\Program Files\Rhino 9`） |
| Grasshopper | Grasshopper 2（`Plug-ins\Grasshopper2`，GH1 同时保留用于对照） |
| 组件总数 | **1416 个**（官方 GH2 文档口径，按工具栏分组） |
| 手册语言 | 简体中文为主，英文原名并列（组件名、端口名、术语保留英文） |

```markdown

**官方页面**：[rhino3d.com/docs/grasshopper2/specs/...](...)

|---|---|---|---|
```

## 5. 原厂图标方案

用户明确要求「用原厂的组件电池图片」。图标来源与处理方式如下：

### 5.1 图标本体

- 图标内嵌在 `Grasshopper2.dll` 中，共 807 个 `.ghicon` 资源，命名形如 `Grasshopper.Resources.Icons.ParameterPoint.ghicon`。
- `.ghicon` 是 GH2 私有矢量格式（二进制），**不能直接当图片引用**。
- GH2 提供官方渲染 API：`Grasshopper2.UI.Icon.AbstractIcon.FromStream(...)` + `DrawToBitmap(Eto.Drawing.Size, int, Color)`，可输出透明底 PNG。

### 5.2 导出路径（按优先级）

| 方案 | 做法 | 结论 |
|---|---|---|
| A（推荐） | 在 Rhino 9 内运行一次性导出脚本，用上述官方 API 把 807 个图标批量渲染为 PNG（多尺寸：24/48/96） | 保真度最高，纯官方渲染 |
| B（备选） | 从官方文档站对应组件页抓取图标资源 | 与官方网页一致，但需逐页抓取 |
| C（兜底） | Rhino 9 中放置组件后画布截图 | 仅用于个别无图标组件 |

> 本机已实测：在 Rhino 外部用反射调用该 API 时图标解析返回空（依赖 GH2 运行时初始化），因此**导出脚本必须在 Rhino 9 进程内执行**。这是 M0 的首要验证项。

### 5.3 命名与目录规范

```
assets/icons/
├── 24/                  ← 列表用（索引页图标网格）
│   ├── ParameterPoint.png
│   ├── CurveAnalysis_CurveCurvature.png
│   └── ...
├── 48/                  ← 详情页大图
└── 96/                  ← 高分辨率/打印
```

命名规则：`{一级分类}_{二级分类}_{组件英文名去空格}.png`，全小写，与 `components.json` 中的 `icon` 字段一一对应。

## 6. 数据流水线

手册采用「数据驱动 + 页面生成」，避免 1416 个组件手工维护。

```
官方在线索引 ──┐
官方 .spec   ──┼─→ 抓取/解析 ─→ data/components.json ─→ 生成页面 ─→ site/
本机组件枚举 ──┘                      │
                                      ├─→ data/terms.json（568 条）
                                      └─→ data/categories.json
GH2 .ghicon ─→ Rhino 内导出 ─→ assets/icons/*.png ─┘
```

### 6.1 核心数据文件

| 文件 | 内容 | 生成方式 |
|---|---|---|
| `data/components.json` | 每个组件：ID、英文名、中文名、一级/二级分类、图标路径、输入输出端口、官方说明、官方链接、示例文件 | 抓取 + 人工校对 |
| `data/categories.json` | 分类树与顺序（对齐 GH2 工具栏） | 从官方索引抓取 |
| `data/terms.json` | 568 条术语中英对照 | 解析 `.term` + 翻译 |
| `data/meta.json` | 版本号、生成时间、来源清单、条目总数 | 构建时写入 |

### 6.2 中文化策略（分三级）

| 级别 | 范围 | 做法 |
|---|---|---|
| P0 精译 | 高频组件约 200 个（曲线/曲面/数据树/数学/参数） | 人工翻译 + 补使用场景与坑位 |
| P1 标准译 | 其余组件 | 术语表约束下的半自动翻译 + 抽查校对 |
| P2 原样 | 极冷门组件 | 保留官方英文说明，仅译名称与端口 |

原则：**端口名称不翻译**（保留 X / Y / Pt 等原厂符号），避免与界面脱节。

## 10. 质量标准

1. **可核查**：每条组件说明必须能对应到官方页面或本机 `.spec`，不得凭空描述。
2. **可运行**：所有示例均来自官方 `.ghz` 或在 Rhino 9 + GH2 中实测通过。
3. **一致性**：组件名、端口名、术语译名与 `terms.json` 完全一致。
4. **完整性**：条目四要素（图标 / 分类 / 端口表 / 官方链接）齐全。
5. **可维护**：数据与页面分离，官方更新时只需重跑流水线。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| GH2 仍在快速迭代，组件会增删 | 数据快速过期 | 所有数据文件带 `gh2Version` 字段；重跑流水线即可更新 |
| `.ghicon` 私有格式无法在 Rhino 外解析 | 图标导出受阻 | 在 Rhino 进程内导出；已验证 API 存在，M0 先做 5 个样本验证 |
| 组件数量大（1416），中文翻译成本高 | 交付周期长 | 三级翻译策略，P0 高频优译，其余半自动 |
| 官方说明为英文，术语译法易不统一 | 阅读体验差 | 先建术语表，再译组件，翻译时强制引用术语表 |
| 图标与说明版权属 McNeel | 合规风险 | 明确署名与非商用声明，不修改图标本体 |
