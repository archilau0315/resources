## 1. 项目定位

### 1.1 一句话定义

一套面向中文用户的 **Ladybug Tools 双语教程 + 全量组件速查站**：用原厂电池图标做视觉索引，覆盖 Ladybug、Honeybee、HB-Energy、HB-Radiance 四个标签页共 **412 个组件**，配官方英文原文、中文释义、端口表、所属章节与工作流配方。

### 1.2 要解决的问题

| 现状 | 本项目 |
|---|---|
| 官方文档只有英文，且分散在 4 个 Primer 站点 | 中文为主、英文并列，一个站点查完 |
| 412 个组件图标长得像、名字长，新手认不出 | 原厂图标 + 中文名 + 分类树，看图找组件 |
| 教程讲“怎么做”，手册讲“是什么”，二者割裂 | 正文里内联组件卡片，点击直达速查条目 |
| 国内资料多为 0.x 旧版（Ladybug + Honeybee 分离时代） | 统一按 1.x 新架构（HB-Energy 基于 OpenStudio）讲 |
| 气象数据、太阳轨迹被当成“前置知识”跳过 | 单列 Part 1，EPW / 太阳 / 舒适度讲透再进建模 |

### 1.3 明确不做

- 不含 Dragonfly（城市尺度）与 Pollination 云平台教程
- 不提供 `.gh` 源文件下载（本机未注册 GH 插件，无法验证可运行性）；示例统一用“组件连线图 + 参数表”
- 不做云端模拟与结果托管，只讲本地 Grasshopper 工作流

### 2.2 图标提取可行性（已实测）

`.ghuser` 是 **raw deflate 压缩的 GH 二进制档案**，解压后含 `Category / SubCategory / Name / NickName / Description / Icon` 等数据块，其中 `Icon` 块为完整的 **24×24 PNG**。

```
读取 → zlib.decompress(data, -15) → 定位 \x89PNG … IEND → 存盘
```

已用 `HB Room.ghuser` 验证成功，提取到标准 24×24 彩色图标。批量导出后再用 Pillow 生成 48 / 96 两档（最近邻 + 轻微锐化，保持像素风清晰）。

## 5. 速查手册设计

### 5.1 条目字段

| 字段 | 来源 | 说明 |
|---|---|---|
| 图标 | `.ghuser` Icon 块 | 24/48/96 三档 |
| 英文名 / 昵称 | `.ghuser` Name / NickName | 原名不改 |
| 中文名 | 人工译名表 | 412 条逐条校订 |
| 所属 | Category + SubCategory | 四标签页 + 23 子分类 |
| 英文说明 | `src/*.py` docstring 首段 | 官方原文，不改写 |
| 中文说明 | 人工翻译 | 与英文一一对应 |
| 输入端口 | docstring `Args` | 名称、类型、必填（`_` 前缀判定）、说明 |
| 输出端口 | docstring `Returns` | 同上 |
| 关联 | 章节映射、同类组件 | 站内互链 |
| 版本 | `ghenv.Component.Message` | 如 1.9.0 |

### 5.2 交互

- 左侧四棵树：Ladybug / Honeybee / HB-Energy / HB-Radiance，展开到子分类
- 顶部搜索：中英文名、昵称、端口名、说明全文；<kbd>/</kbd> 聚焦、<kbd>Esc</kbd> 清空
- 筛选：按标签页、子分类、是否有中文译名
- 卡片：32px 图标 + 中英名 + 子分类；点开为右侧详情抽屉（端口表 + 原文 + 链接）
- 教程页内联组件：正文中的 `HB Room` 自动渲染为小卡片，悬停显示端口，点击跳速查
- 明暗双主题、打印样式、移动端单列

### 5.3 技术形态

**零依赖静态站**（纯 HTML / CSS / JS，无框架、无构建、无 CDN），与 gh_guide 同构，保证离线可用、双击可开、服务器直接托管。

## 7. 数据流水线

```
① extract_icons.py
   .ghuser → raw inflate → 提取 Icon PNG → Pillow 生成 24/48/96
   输出：assets/icons/**、reports/icons_missing.txt（目标 0 条）

② parse_components.py
   .ghuser → Name / NickName / Category / SubCategory / Description / Message
   src/*.py → docstring Args / Returns
   合并输出：data/raw_components.json（412 条 + 未匹配报告）

③ build_data.py
   叠加 中文译名表（人工） + 章节映射（人工） → data/components.json

④ check_data.py
   校验：字段完整率、图标存在率、端口数与 docstring 一致性、站内链接
   输出：构建报告（失败即中止）
```

中间产物（`raw_components.json`、报告）留在 `tools/` 或临时目录，不进交付目录。
